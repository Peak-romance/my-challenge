在 D 盘发现一套**"公共资产闲置平台"**全栈代码（目录 `D:\闲置平台代码`）：

- README 声称：功能完整、**91 项端到端断言全部通过**、11 个页面 jsdom 渲染零错误、开箱即用。

但代码处于**"闲置"**状态——它从未在本机真实跑通过，只有文档声称。这正是 C8「真实项目落地」要解决的问题：**让一个"文档完美但没人维护、跑不起来"的遗留系统，在真实约束下真正可运行、可验收。**

## 4. 真实约束（Real Constraints）

| 约束 | 说明 | 对项目的影响 |
| --- | --- | --- |
| 无 Docker | 本机未安装 Docker | 只能走"免 Docker"路径（uvicorn 直启 + 脚本） |
| Python 3.13 | 解释器为 3.13.12 / 3.13.14 | `requirements.txt` 锁 `pydantic==2.10.4` → 其依赖 `pydantic-core==2.27.2` **无 cp313 轮子**，安装直接失败 |
| 双 Python 解释器 | shell `python` 指向 WorkBuddy 管理的 `3.13.12`；裸 `pip` 指向另一处 `3.13.14` | 裸 `pip install` 后 `python` 找不到包（环境错位） |
| 企业镜像源不稳定 | 对大依赖树偶发卡死 / 截断 JSON | 需分批安装、后台任务 + 日志 |

这些约束**文档里完全没写**——它们只有在"真正去跑"时才会暴露，是真实项目与练习的核心差异。

## 7. 风险与应对

- **镜像源不稳定** → 依赖分批安装 + 后台任务 + 日志文件，避免 `uvicorn[standard]` 放大依赖树。
- **双 Python 错位** → 全程统一使用 `python -m pip`，杜绝裸 `pip`。
- **版本锁导致不可装** → 将死锁版本改为兼容区间/已验证版本，并在文件内注释原因。
