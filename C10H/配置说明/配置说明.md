## 0. 先记住这一条

**Windows 上的 Hermes 家目录不是 `~/.hermes`，而是 `%LOCALAPPDATA%\hermes`。**

实测输出：

```
hermes config path      → C:\Users\WRM\AppData\Local\hermes\config.yaml
hermes config env-path  → C:\Users\WRM\AppData\Local\hermes\.env
```

绝大多数中文教程写的 `~/.hermes/config.yaml` 在本机**不存在**。按教程找文件的第一个坑就在这里。

## 2. `config.yaml` 的 29 个顶层键

```
_config_version  database  runtime  attachments  plugins  model  kanban  cron
terminal  browser  tool_loop_guardrails  compression  prompt_caching  memory
max_concurrent_sessions  group_sessions_per_user  hosted_rooms  streaming
skills  agent  gateway  platform_toolsets  stt  code_execution  delegation
display  telemetry  auth  updates
```

**关键认知：这是一份"全注释模板"。** 未显式写出的键走代码默认值，不是"缺失"。
判断生效值要用 `hermes config get <dotted.key>`，不要靠肉眼读 yaml。

本机实测生效值：

```powershell
hermes config get model.default    # anthropic/claude-opus-4.6
hermes config get model.provider   # auto
hermes config check                # Config version: 53 ✓
```

### 我关注的几个段

| 段 | 作用 | 本机取值 |
| --- | --- | --- |
| `model` | 默认模型 + provider 选择 | `auto` + `anthropic/claude-opus-4.6` |
| `terminal` | 终端后端（local/docker/ssh/daytona/modal/singularity） | 运行时显示 `local`，`sudo` disabled |
| `tool_loop_guardrails` | 防死循环：同名工具连续失败 3 次、同签名失败 5 次即熔断 | 启用（见 `status`） |
| `compression` | 上下文压缩 | 默认 |
| `prompt_caching` | 提示词缓存 | 默认 |
| `memory` | 内置 MEMORY.md / USER.md 开关 + 外部记忆 provider | 内置开启，未接外部 |
| `skills` | 技能开关与注入策略 | 44 内置启用 |
| `cron` | 调度器行为（含 `catch_up_missed`） | 1 个任务 |
| `gateway` | 消息网关（24 个平台适配器） | 未配置任何平台 |
| `delegation` | 子 Agent 委派 | 默认 |
| `display` | TUI 显示 | 默认 |

## 4. 模型接入：四条路线

Hermes 本身不含模型。按"改动面从小到大"排序：

### 路线 A · 交互向导（推荐给人用）

```powershell
hermes model            # 选择 provider → 填 key → 选默认模型
hermes model --refresh  # 清缓存，重新拉取各 provider 的 /v1/models
```

### 路线 B · DeepSeek（国内直连，本机最现实的选择）

本机 `hermes config check` 已确认支持 `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL`：

```powershell
# 1) 写密钥（只进 .env，不进任何交付文档）
Add-Content "$env:LOCALAPPDATA\hermes\.env" "DEEPSEEK_API_KEY=sk-你的key"

# 2) 指定 provider 与模型
hermes config set model.provider "deepseek"
hermes config set model.default  "deepseek-chat"

# 3) 验证
hermes status --full | Select-String "DeepSeek|Model|Provider"
```

### 路线 C · 任意 OpenAI 兼容端点（vLLM / Ollama / 中转站）

```
model:
  provider: custom
  base_url: https://your-endpoint/v1
  default: your-model-name
```

密钥走 `OPENAI_API_KEY`。`ollama` / `vllm` / `llamacpp` 三个别名都会映射到 `custom`。

### 路线 D · 纯环境变量（不改配置文件，适合临时试验）

```powershell
$env:OPENAI_BASE_URL = "https://your-endpoint/v1"
$env:OPENAI_API_KEY  = "sk-..."
hermes
```

**本次未接入任何模型**（用户决定）。因此 `hermes` 交互会话可启动但无法完成推理；
所有"需要模型才能验证"的项，本文档均标注为**未验证**，不做无根据的断言。

> 验证方式（接好 key 后应做）：`hermes -z "用一句话说明你读到的 USER.md 第一条内容"`，
> 若回答命中画像内容，说明记忆注入链路通了。

## 5. 记忆系统：三层，各有各的落点

| 层 | 载体 | 生命周期 | 本机状态 |
| --- | --- | --- | --- |
| 短期 | `sessions\`（FTS5 索引） | 会话级，可检索 | 0 活跃会话 |
| 长期 | `memories\MEMORY.md` + `USER.md` | 跨会话、跨重启 | **已写入（本次）** |
| 肌肉记忆 | `skills\` | 跨会话，按需加载 | 44 内置 + 1 自定义 |

### 已写入的内容（本次个性化）

- `memories\USER.md`（1001 字符）：称呼/语言/时区、**交付按编号归档的偏好**、
  "反感纸面完成"的验收标准、本机注入守卫与网络事实、协作边界（删除/外发先确认）。
- `memories\MEMORY.md`（1393 字符）：HERMES_HOME 实际路径、独立 Python 位置、
  四个环境陷阱（乱码 / schtasks / PyPI / 证书过期）、模型接入状态。
- `SOUL.md`：在原人格基础上追加「本机定制」段——默认中文、先取证再下结论、
  区分事实与推断、失败留痕、不写空话文档、破坏性动作先确认。

### 为什么这样分工

`USER.md` 只放**关于人**的稳定事实，`MEMORY.md` 只放**关于环境**的稳定事实，
`SOUL.md` 只放**行为准则**。混在一起会导致：换机器时画像被环境细节污染、
人格被当成知识检索。这是分层记忆真正的价值，不是营销话术里那句"它记得你"。

### 记忆的运维命令

```powershell
hermes memory status     # 当前记忆 provider 配置
hermes memory off        # 关掉外部 provider，回落到内置两文件
hermes memory reset      # 清空内置记忆（谨慎）
```

## 6. 技能系统

### 目录与最小结构

```
%LOCALAPPDATA%\hermes\skills\
├─ productivity\ ...        # 内置分类（12 个）
└─ c10h-delivery-audit\     # ← 本次自定义
   ├─ SKILL.md              # 必需：YAML frontmatter + Markdown 正文
   └─ scripts\audit.py      # 可选：确定性脚本，可脱离模型独立运行
```

`SKILL.md` 的 frontmatter 字段（照内置技能格式）：

```yaml
---
name: c10h-delivery-audit
description: "一句话说明何时该用"
version: 1.0.0
author: user
license: MIT
platforms: [windows, linux, macos]
metadata:
  hermes:
    tags: [交付审计, 目录巡检]
    related_skills: []
---
```

### 注册与验证（已实测）

```powershell
hermes skills list      # → │ c10h-delivery-audit │ │ local │ local │ enabled │
hermes skills audit     # 安全审计已安装技能
hermes skills config    # 交互式启停单个技能
```

**"被列出"才是注册成功的唯一证据**，文件写进目录不等于注册成功。

### 设计要点：为什么把逻辑放脚本里

SKILL.md 负责"什么时候用、怎么解释"，`scripts/audit.py` 负责"确定性地做"。
这样同一能力有两种调用方式：Agent 调度（需模型），或人直接 `python audit.py`（不需模型）。
**这不是为了好看，是为了在模型不可用时，能力依然可验证。**

## 7. 定时任务

### 已创建（实测跑通）

| 项 | 值 |
| --- | --- |
| Job ID | `de7e53f5db3b` |
| 名称 | 每日交付物巡检 |
| 调度 | `0 9 * * *`，时区 `Asia/Shanghai` |
| 模式 | **`--no-agent`**（不调用 LLM） |
| 脚本 | `%LOCALAPPDATA%\hermes\scripts\daily-delivery-audit.py` |
| 投递 | `local` |
| 首次手动执行 | `Ran now: succeeded.`，运行记录 `7a3a3b8f… completed` |

### 关键设计：`--no-agent` 是省钱的正确姿势

```
--script 单独用：脚本 stdout 注入 Agent 提示词 → 每 tick 都要一次推理
--script + --no-agent：脚本就是任务，stdout 直接投递 → 零推理成本
```

监控、巡检、告警这类"输出本身就是结论"的任务，一律走 `--no-agent`。

### 前置依赖（本机受限项）

任务能创建、能手动跑，但**自动触发需要调度器**：

```powershell
hermes cron status     # ✗ No scheduler is serving profile 'default'
hermes gateway run     # 前台常驻（推荐先这样验证）
hermes gateway install # 注册为 Windows 服务
```

`gateway install` 在 Windows 上依赖 `schtasks.exe`，本机安全策略将其列入程序黑名单，
**该命令在本会话内不可用**。需在未受限的普通 PowerShell 窗口执行，或直接用
`hermes gateway run` 前台常驻。这是环境限制，已在安装记录中标注。

## 11. 配置故障速查

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| 找不到 `config.yaml` | 按教程去 `~/.hermes` 找 | `hermes config path` 看真实路径（本机在 `%LOCALAPPDATA%\hermes`） |
| `hermes` 命令不存在 | 用户级 PATH 未在新窗口生效 | 新开窗口，或 `. demo\hermes-env.ps1` |
| 中文/边框乱码 | 控制台代码页 936 | `[Console]::OutputEncoding = [Text.Encoding]::UTF8` |
| 自写 `.ps1` 中文报语法错 | UTF-8 无 BOM，PS 5.1 按 ANSI 读 | 存为 UTF-8 **带 BOM** |
| 依赖安装长时间无输出 | PyPI 直连极慢 | 设 `UV_INDEX_URL` 国内镜像 |
| `doctor` 中途出现 `PROGRAM BLOCKED` | `schtasks.exe` 被黑名单拦截 | 环境限制，换未受限终端 |
| `cron` 任务不自动跑 | 无 gateway 进程服务该 profile | `hermes gateway run` / `gateway install` |
| 配置改坏 | — | `hermes config migrate` 补齐；`hermes doctor --fix` 修目录与模板 |

## 12. 一句话总结

配置 Hermes 的实质不是"填几个 key"，而是**分清四类东西各自的落点**：
模型（外部，随时可换）、记忆（本地两文件 + 技能）、行为（SOUL.md）、能力外延（skills + cron）。
分清之后，换模型、换平台、换机器都不会把人格和记忆搞乱。
