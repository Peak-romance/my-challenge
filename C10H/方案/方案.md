# C10H · 交付方案（Challenge 拆解与验收设计）

> 位置：`D:\C10H\方案\方案.md`
> 作用：把"安装并驾驭 Hermes Agent"这句要求，翻译成可执行步骤与可证伪的验收标准。

---

## 1. 对题面的解读

题目给了四条底线（安装记录 / 配置说明 / demo / AI日志）和五维评分（mastery 25、integration 20、
artifactCompleteness 15、aiUsage 20、reflection 20）。

关键观察：**四条交付物与五维评分不是一一对应的**。
- 「复盘质量 20 分」在四条交付物里**没有对应项**，但对应用户默认的 AAR 习惯 → 必须额外产出 `AAR\AAR.md`。
- 「驾驭程度 25 分」是最重的一项，靠"装成功"拿不到，得靠**故障归因深度**与**上游零修改**来体现。

所以本方案的交付结构是"四条底线 + 两处补强"：补 AAR，补方案本身（把评分维度显式对齐）。

---

## 2. 三条硬约束（决定了方案形态）

| 约束 | 来源 | 对方案的直接影响 |
| --- | --- | --- |
| 不提供模型 API Key | 用户选择"暂不接模型" | demo 不能是对话式，必须是**确定性验收** |
| 会话环境有程序黑名单与进程限制 | 本机实测 | 不能派生 `powershell.exe`、不能用 `Start-Job`、`schtasks` 不可用 |
| 中文 Windows + PS 5.1 | 本机环境 | 所有 `.ps1` 必须带 UTF-8 BOM；所有输出需先设 UTF-8 控制台 |

这三条不是障碍，是**设计输入**。方案的价值就在于：在约束下仍然交付"可验证"的东西。

## 3. 执行路径

```
探明（-Manifest 读协议）
  → 分段安装（9 stage，逐段留日志）
    → 逐段归因（宿主 / 网络 / 工具 / 编码 四层）
      → 收敛（镜像、别名、编码前置）
        → 个性化（USER/MEMORY/SOUL + 自定义技能 + cron）
          → 验收（14 条断言 + 自检审计）
            → 复盘（AAR：方法论抽象）
```

详细执行记录见 `..\安装记录\安装记录.md`。

## 4. 交付物与评分维度的对齐

| 评分维度 | 证明手段 | 落点 |
| --- | --- | --- |
| **mastery 25** 驾驭深度 | 分阶段协议执行、四层归因、上游零修改、10 条故障原文 | `安装记录` + `logs\failures.md` |
| **integration 20** 集成质量 | 环境包装器（编码/PATH/镜像三坑一次收敛）、定时任务接入、记忆按本机事实写入 | `demo\hermes-env.ps1` + `配置说明 §9` |
| **artifactCompleteness 15** 产物完整性 | 14 条断言全 PASS、报告落盘、脚本可被第三方重跑、目录结构自洽 | `demo\outputs\report-*.md` |
| **aiUsage 20** AI 使用质量 | 阶段化日志 + 失误入账（3 处自我纠错）+ 决策权交还记录 | `AI日志\AI日志.md` |
| **reflection 20** 复盘质量 | 四层归因模型 + 六步 SOP + 6 条改进（3 条已落地） | `AAR\AAR.md` |

## 5. 验收标准（自建的 8 条 AC）

| # | 断言 | 判据 |
| --- | --- | --- |
| AC1 | 真的装上了 | `hermes --version` 返回 v0.23.1，且代码 HEAD 与锁定提交一致 |
| AC2 | 装的是干净版本 | 上游 `install.ps1`、`hermes-agent` 源码零修改 |
| AC3 | 配置可解释 | 每个路径/版本都在文档中给出实测命令与输出 |
| AC4 | 个性化真实生效 | `skills list` 显示自定义技能 `local/enabled`；cron 任务真实执行过一次 |
| AC5 | 验收可重跑 | `c10h-verify.ps1` 第三方可原地执行，退出码 0 |
| AC6 | 失败有原文 | 10 条故障均保留报错原文与根因判断依据 |
| AC7 | 不夸大 | 未验证项（对话、记忆召回、平台接入）显式列出 |
| AC8 | 能自我审计 | 用自建技能审计本目录，六类交付物齐全 |

AC8 是本次刻意加的：**用自己造的工具审自己的交付**，比自述更有说服力。

---

## 6. 明确不做的事

- 不代填任何 API Key、不代扫码接平台（需本人授权）。
- 不绕过安全策略（`schtasks` 黑名单 → 认边界，降级断言）。
- 不删除安装器遗留的 `tools\.staging-*` 目录（删除动作需先确认）。
- 不把"没模型"包装成"轻量版"——直接写明哪些能力未验证。
