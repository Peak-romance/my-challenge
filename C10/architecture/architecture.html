C10 · Build Your Own Agent

第二大脑：五层架构与 KSTAR 记忆

一个可运行、可审计、会进化的长期智能体。核心主张：智能体的价值不在单次回答的质量，而在跨会话的存续能力——记忆不丢、经验沉淀、重复劳动被自动抽象。

01五层架构

分层的判据只有一个：能不能在不改下层的前提下换掉这一层？五层均通过——换接口只动 L1，换检索只动 L5，换规划器只动 L3（LLM 规划器已实现且失败自动降级）。

L1 · INTERFACE
接口
src/interfaces/
CLI · REPL · HTTP。把外部输入规范化为一次 run()，再把结果格式化回去。不含任何规划、记忆、工具逻辑。
契约：输入文本 → RunResult
判据：删掉这一层，内核仍然完好
▲
L2 · TOOLS
工具
src/tools/ · 20 个
智能体唯一的"手"。fs / memory / skill / shell / http / format。所有副作用必经此处，因此"它到底动了什么"永远可审计。
契约：声明式参数 + danger 分级 + 路径沙箱
铁律：禁止静默失败
▲
L3 · LOOP
循环
src/core/loop.py
perceive → recall → plan → act → observe → reflect → persist。只做分发、守预算、记账，业务逻辑一律下沉，避免上帝对象。
契约：永远返回 RunResult，失败不抛异常
预算：步数 / 超时 / 输出三重熔断
▲
L4 · SKILLS
技能
skills/ · 6 个上线
把重复任务固化为声明式契约（skill.json + SKILL.md）。可校验、可组合、可被挖掘、可被替换。技能里没有代码。
契约：步骤 + 输入 + 错误策略 + 输出模板
演化：挖掘草案 → 人工闸门 → 上线
▲
L5 · MEMORY
记忆（KSTAR）
src/memory/
四层记忆：知识 / 状态 / 轨迹 / 归档。写入有策略、读取有排序、定期有巩固与遗忘。越用越准，而不是越用越乱。
契约：KStar 是唯一读写入口
铁律：T 层只追加、A 层必带证据

03KSTAR 四层记忆

四层不是四种数据格式，而是四个不同的问题。问题不同，写入权限就不同——这是防止记忆退化成"第二份笔记堆"的关键。

KKnowledge · 知识

"关于这个世界/这个人，什么是稳定成立的？"

  • 只接受显式写入，不允许系统"顺手猜一条"
  • 同文去重：重复只加权，不重复膨胀
  • 闲置衰减 + 归档（不物理删除）
memory/k/knowledge.jsonl
SState · 状态

"此刻在做什么？什么还没闭环？"

  • 每轮自动更新，只收结构化字段
  • 未闭环事项归一化去重（同一件事只登记一次）
  • 容量上限：recent 10 / open_loops 12
memory/s/state.json
TTrajectory · 轨迹

"上次到底发生了什么？"

  • 全量追加，任何路径不得回改
  • 按天分片，可回放、可挖掘
  • 不进上下文（只用于复盘与进化）
memory/t/<date>.jsonl
AArchive · 归档（R=Reflection）

"从那次经历里学到了什么？"

  • 只能由反思模块写入，每次至多 1 条
  • 必须带 evidence：指回 T 层 run_id
  • 同类同文合并加权，防教训灌水
memory/a/lessons.jsonl

04三个闭环：为什么它是基础设施

一个"项目"完成任务就结束；一个"基础设施"必须在使用中变强。这里的变强不是宣言，而是三条可观测的回路。

运行任务→ T 层轨迹（工具序列签名）→ 挖掘器：support ≥ 2→ 技能草案 _proposed/→ 人工确认语义 / 补参数→ --promote 上线→ 下次同指令直接走技能

实测案例：几条"记住 + 记待办"的组合指令 → 挖掘出草案 auto-memory-remember-memory-open-loop → 人工确认后上线为 memorize-loop → 此后同类指令的 trace 中 plan 直接显示「该组合已被技能覆盖 → 走技能（进化闭环）」。

闭环信号动作证据
记忆闭环召回命中 / 未命中命中强化权重；未命中登记 recall_miss 暴露知识缺口K 层 use_count 递增
能力闭环相同工具序列重复生成草案 → 人工闸门 → 上线为技能logs/mining-report.md
契约闭环技能引用坏工具 / 输入缺失装载期告警隔离；自检技能显性暴露self-check 的「契约校验」段

05运行边界与可审计性

维度策略为什么这样设计
路径相对路径一律相对项目根 C10/；越界拒绝。读、写同界。"读得到但写不进"的割裂会让技能无法自证（曾导致巡检解析到不存在的目录）
危险分级danger 0/1/2：只读 / 写 / 执行；2 需显式授权把"能做什么"变成声明，而不是靠人记住
命令首命令白名单（python / git / ls / grep…），其余拒绝白名单比黑名单更可维护
预算步数 30 / 单工具 20s / 单次 180s / 输出 4000 字失控的工具链比失败的任务更贵
审计每条轨迹固定含 run_id / plan / recall / steps / lesson事后能回答"想干什么、依据什么、动了什么、学到什么"
