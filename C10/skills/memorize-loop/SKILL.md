# memorize-loop · 记住并开待办

## 这个技能解决什么
真实指令经常是"一句话两件事"：**"记住 X，另外记个待办 Y"**。
人脑可以同时处理，但对智能体来说这是两种不同的写入（K 层语义记忆 / S 层工作状态）。

## 它是怎么来的（这是本技能最重要的部分）
**它不是人手工设计的，是系统自己挖掘出来的。**

```
3 次"记住 + 记待办"的组合指令
   → T 层留下相同工具序列的轨迹（memory.remember → memory.open_loop）
   → 挖掘器 support ≥ 2 → 生成草案 skills/_proposed/auto-memory-remember-memory-open-loop/
   → 人工确认语义、补 inputs 与 triggers、替换 <从轨迹补全> 占位参数
   → python agent.py --promote ... → 本技能上线（v1.0.0，status=active）
   → 此后再出现同样组合，规划器直接走本技能（trace 中 rationale 显示"进化闭环"）
```

草案原件仍保留在 `skills/_proposed/` 作为证据——它记录了"自动发现"与"人工确认"之间的差距：
草案里的参数是占位符，直接上线会让技能往 K 层写垃圾。这条差距正是人工闸门存在的理由。

## 契约
| 输入 | 必填 | 说明 |
| --- | --- | --- |
| fact | 是 | 要沉淀进 K 层的稳定事实（会被去重与加权） |
| loop | 是 | 要登记进 S 层的未闭环事项（会被归一化去重） |

| 步骤 | 工具 | 结果 |
| --- | --- | --- |
| k | `memory.remember` | 返回 `{id, dedup, importance}`，模板取 `.id` |
| s | `memory.open_loop` | 返回确认文本 |

## 错误策略
`on_error: abort` —— 双写必须是原子的。
如果"记忆写了但待办没记"，用户会以为两件事都办了；这种**半成功的假象**比彻底失败更有害。

## 与多意图分解的关系
`planner._compose` 也能处理"记住 A；待办 B"，但那是**临场拼装**，每次都要重新解析、重新验证。
本技能提供的是**有名字、有契约、可被测试的稳定路径**。这就是"抽象"与"临时应付"的差别：
前者可以进版本库被 review，后者只能活在当次上下文里。

## 已知边界
- 只接受"一条事实 + 一条待办"。多条待办请分次调用（或后续扩展为 `loops: list`）。
- 不判断事实的**真伪**与**稳定度**——写什么由调用方决定，本技能只负责落库。
